TECHNICAL CONTRIBUTION · 1 OCTOBER 2026

Aurora Studio expands upstream technical contributions to openOMSI.

Commercial OMSI experience meets open-source compatibility work.

HONG KONG, 1 October 2026 — Aurora Studio has expanded its technical involvement in openOMSI, contributing upstream compatibility fixes and Asian interface localisation while testing existing OMSI content, including OMSI 2 Add-on: Project Numazu, against the emerging open-source simulator.

Project Numazu combines a large map, scenery objects, passenger assets, AI traffic, scripts and legacy OMSI behaviours. Aurora Studio is using that production-scale content as a practical compatibility testbed: when a problem appears, the studio investigates whether it is specific to the add-on or reflects a wider OMSI behaviour that may affect other maps and vehicles.

Upstream work already merged

Since 29 September 2026, Aurora Studio founder Shiko Leung, contributing on GitHub as Shiko215, has submitted six substantive pull requests to the upstream turbo-devv/openOMSI repository. Five had been merged by 1 October, with one further compatibility change under review.

  • PR #88 — Asian interface localisation contributed by Aurora Studio.
  • PR #103 — indexed parking lists, scenery free textures and decorative splines.
  • PR #198 — scenery free-texture filenames produced in frame scripts.
  • PR #199 — low-density random traffic compatibility.
  • PR #201 — preserving AI pool rules through random traffic routing.
  • PR #455 — map-specific nested passenger-pack compatibility, under review at the time of publication.

From commercial add-on development to ecosystem compatibility

The purpose of this work is broader than making one add-on run. Commercial OMSI content exposes combinations of assets and legacy behaviours that can be difficult to reproduce in a small test scene. By tracing those cases and contributing suitable fixes upstream, Aurora Studio aims to help openOMSI interpret more of the existing OMSI ecosystem faithfully.

The studio is also contributing from an Asian development perspective. Interface localisation and compatibility testing with Japanese transport content can help reduce barriers for users and creators whose OMSI libraries extend beyond the simulator's original European focus.

An independent open-source project

openOMSI is an independent open-source project. Aurora Studio's current involvement is as an upstream contributor through compatibility testing, localisation and code contributions. This announcement does not describe Aurora Studio as the owner, operator or official technology partner of openOMSI.

Project Numazu remains a commercial OMSI 2 add-on distributed through its existing publishing channels. Aurora Studio intends to continue testing relevant OMSI content and contributing suitable fixes where they can benefit the wider community.
